## Quick reference

| Topic | Where |
| --- | --- |
| Live host | `https://api.getmetacognition.com` |
| Auth header | `Authorization: Bearer <access_token>` |

Small surface: **`/me`**, **`/ingestion/memory`**, **`/recall`**, **`/usage/*`**.

## Base URL

```
https://api.getmetacognition.com
```

## Auth

Every product endpoint expects:

```http
Authorization: Bearer <access_token>
```

You mint `<access_token>` by posting your API key to [`POST /auth/token-exchange`](/api-reference/auth/token-exchange). After that you treat it like any short-lived bearer token.

## Content type

Always:

```http
Content-Type: application/json
```

## Correlation IDs

Each request should carry (or receive) an `X-Correlation-ID` UUID. The server mints one if you skip it; the SDK always sends its own so your service logs and ours match. Paste that value into support threads.

```http
X-Correlation-ID: 4f1d8e3c-2a9b-4c0d-9e6f-1a2b3c4d5e6f
```

## HTTP errors

Standard HTTP status codes:

| Status | Meaning |
| --- | --- |
| `200` | OK |
| `201` | Created (signup, key creation) |
| `202` | Accepted (async ingestion) |
| `204` | No content (key revoke) |
| `400` | Bad payload |
| `401` | Auth failure |
| `403` | Forbidden |
| `404` | Not found |
| `422` | Validation error (FastAPI shape) |
| `429` | Daily quota exceeded |
| `5xx` | Tex platform fault—retry with backoff, then escalate with the correlation ID |

Error body shape:

```json
{
  "error": "HTTP 401",
  "message": "Invalid token",
  "details": null,
  "timestamp": "2026-05-08T10:00:00Z",
  "request_id": "..."
}
```

## Rate limits

<Info>
  Limits are per organization. Today the free tier allows **1,000,000** `tokens_in` and **5,000,000** `tokens_out` each UTC day, resetting at **00:00 UTC**. See [Usage, quotas, and billing](/concepts/usage-billing) for how that shows up in responses and dashboards.
</Info>

## Retries

You should retry **twice** with exponential backoff on `408`, `500`, `502`, `503`, `504`, and hard network failures. Respect `Retry-After` when the API sends it.

Skip retries for `400`, `401`, `403`, `404`, `422`, and `429`—those will not magically clear on a replay.
