---
title: "Deletions"
description: "Soft-delete a memory, a scope, or a user in your org, and fetch the receipt."
---

Both endpoints require an **org admin** token: exchanged **without** `user_id` from a key with `admin` or `*`. Per-user tokens are refused with `403`. The org always comes from the token.

A deletion hides the target from every read path — active recall, deep recall, search, `GET /v4/memories` — as soon as the request returns, and withdraws its vectors. It is a **soft** delete: storage is reclaimed after the retention window (7 days by default), when Tex runs the purge. See [Deletions](/sdk/deletions) for the model and its limitations.

## `POST /me/deletions`

```http
POST /me/deletions
Authorization: Bearer <org_admin_token>
Content-Type: application/json
```

```json
{
  "target": {"kind": "user_scope", "value": "alice"},
  "reason": "GDPR erasure request",
  "idempotency_key": "erasure-412",
  "mode": "soft"
}
```

<ParamField body="target" type="object" required>
  What to delete.

  <Expandable title="properties">
    <ParamField body="kind" type="string" required>
      | `kind` | `value` | Deletes |
      | --- | --- | --- |
      | `memory` | A memory id | One memory written with `/v4/memories` (`memories.add`), in long-term and active memory. Requires `owner_user_id` |
      | `user_scope` | A user id | Everything in that user's `user:<value>` scope |
      | `scope` | A scope id, e.g. `team:eng` | Everything written to that scope by its members, and every membership of it. `org:` scopes are refused |
      | `user` | A user id | The user's personal-scope data, their scope memberships, and their active-memory data |
    </ParamField>
    <ParamField body="value" type="string" required>
      1–512 chars. For `kind: "scope"`, a canonical `"<kind>:<value>"` id.
    </ParamField>
    <ParamField body="owner_user_id" type="string">
      **Required for `kind: "memory"`**: the user whose memory this is. Only the owner can delete it, and there is no default — a missing or empty value returns `422`. Echoed back in the receipt's `target`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="reason" type="string">
  Free text stored on the receipt, ≤ 2,000 chars.
</ParamField>

<ParamField body="idempotency_key" type="string">
  ≤ 256 chars. A repeated key in the same org returns the first receipt with `"replayed": true` instead of running again.
</ParamField>

<ParamField body="mode" type="string" default="soft">
  Only `soft` is accepted here. `purge` returns `400`.
</ParamField>

### Response — `200`

The receipt:

<ResponseField name="request_id" type="string">
  Receipt id (UUID). Use it with `GET /me/deletions/{request_id}`.
</ResponseField>

<ResponseField name="status" type="string">
  `completed` when every tier did everything it was asked; `partial` when an item was refused or a tier reported errors. A `memory` deletion is `completed` only when the long-term delete and the active-tier tombstone both succeeded.
</ResponseField>

<ResponseField name="purge_after" type="string | null">
  ISO 8601 time the retention window ends.
</ResponseField>

<ResponseField name="replayed" type="boolean">
  `true` when this receipt was returned for a repeated `idempotency_key`.
</ResponseField>

<ResponseField name="tiers" type="object">
  Per-store outcome. Each tier has `status` (`ok` / `partial` / `error` / `skipped`) and `errors` (list of strings).

  <Expandable title="tiers">
    <ResponseField name="helixdb" type="object">
      Long-term memory: `deleted`, `refused` (items only their owner can delete), `skipped_unscoped` (items with no scope, left alone by a shared-scope deletion). For `kind: "memory"`, `status` is `not_found` when nothing was deleted, and the tier also has `episode_events_deleted` (the memory's consolidated episode events removed; always present) and `episode_events_refused` (only when some were refused). An episode-event failure is added to `errors` as `"episode events: …"` and makes the tier and the receipt `partial`.
    </ResponseField>
    <ResponseField name="active_memory" type="object">
      Active memory: `fragments_deleted`, `kv_keys_deleted`, `episodes_tombstoned`, `episodes_deleted`.

      For `kind: "memory"` the shape is `{"status", "tombstones_written", "errors", "note"?}`, with `status`:
      - `ok` — hidden from active recall (`tombstones_written: 1`)
      - `not_located` — the memory couldn't be read for this owner, or it isn't a `/v4/memories` memory (conversation turns from `/ingestion/memory` aren't addressable one by one — delete their `user_scope` or `scope`)
      - `skipped` — the long-term delete didn't succeed, so the active copy was left alone
      - `error` — the active tier failed; see `errors`
    </ResponseField>
    <ResponseField name="auth_db" type="object">
      Access grants, routing, and billing rows: `scope_memberships_deleted`, `episode_registry_deleted`, `episode_registry_retained`, `usage_events_deleted`, `usage_events_retained`. Usage events always survive a soft deletion.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="not_covered" type="array">
  Stores this deletion did not touch, as `{"tier", "reason"}`. Always includes `ingestion_pipeline` and `object_storage_s3`; a `scope` deletion adds `episode_registry`.
</ResponseField>

Also returned: `org_id`, `target` (`kind`, `value`), `mode`, `requested_by`, `requested_via` (`org_admin`), `reason`, `created_at`, `completed_at`.

```json
{
  "target": {"kind": "memory", "value": "<memory id>", "owner_user_id": "alice"},
  "status": "completed",
  "tiers": {
    "helixdb": {"status": "ok", "errors": [], "deleted": 1, "refused": 0, "skipped_unscoped": 0, "episode_events_deleted": 1},
    "active_memory": {"status": "ok", "errors": [], "tombstones_written": 1},
    "auth_db": {"status": "ok", "errors": [], "scope_memberships_deleted": 0, "episode_registry_deleted": 0, "episode_registry_retained": 0, "usage_events_deleted": 0, "usage_events_retained": 0}
  },
  "…": "…"

```

A `user` target in soft mode also carries `tiers.auth_db.note`, explaining that usage events and routing rows are kept until purge.

## `GET /me/deletions/{request_id}`

```http
GET /me/deletions/{request_id}
Authorization: Bearer <org_admin_token>
```

Returns the stored receipt. A receipt from another org returns `404`. After the purge has run, the receipt also carries a `purge` object with the purge's own receipt.

## Errors

| Status | `message` | When |
| --- | --- | --- |
| `400` | `Only soft deletions can be requested here. …` | `mode` is not `soft` |
| `401` | | Missing or invalid token |
| `403` | `Requires an org admin key (admin/*) on a token not minted for a specific user` | Per-user token, or a key without `admin` / `*` |
| `403` | `Deleting an org-wide scope removes every member's shared memory; contact support — this is a platform operation.` | `kind: "scope"` with an `org:` value |
| `404` | `No user '<id>' is known in this organization` | `user` / `user_scope` target your org has no record of |
| `404` | `Deletion request not found` | `GET` of an unknown or another org's receipt |
| `422` | `owner_user_id is required for kind=memory: the user whose memory this is` | `kind: "memory"` without `owner_user_id` |
| `422` | | Unknown `kind`, empty `value`, malformed scope id, field too long |

## Not supported yet

- **One document or one conversation on its own.** `DELETE /v3/documents/{id}` returns `409` for documents added through the ingestion pipeline. Delete the scope or user the content lives in instead. Per-document deletion is planned.
- **Ingestion records and raw uploaded files** are not deleted (see `not_covered`).

## Examples

<CodeGroup>
```bash cURL
BASE=https://api.getmetacognition.com

# Delete a team scope
curl -s -X POST $BASE/me/deletions \
  -H "Authorization: Bearer $ORG_ADMIN_JWT" -H 'content-type: application/json' \
  -d '{"target":{"kind":"scope","value":"project:budget-cycle-2026"},"reason":"project closed","idempotency_key":"close-bc-2026"}'

# Delete one memory owned by alice
curl -s -X POST $BASE/me/deletions \
  -H "Authorization: Bearer $ORG_ADMIN_JWT" -H 'content-type: application/json' \
  -d '{"target":{"kind":"memory","value":"<memory id>","owner_user_id":"alice"}}'

# Re-read a receipt
curl -s $BASE/me/deletions/3b9d6c1e-5f2a-4c8e-9a71-0d2e4b6f8a10 \
  -H "Authorization: Bearer $ORG_ADMIN_JWT"
```

```python Python SDK
receipt = admin.deletions.delete_scope("project:budget-cycle-2026",
                                       reason="project closed",
                                       idempotency_key="close-bc-2026")
admin.deletions.delete_memory(mem_id, owner_user_id="alice")
admin.deletions.get(receipt.request_id)
```
</CodeGroup>
