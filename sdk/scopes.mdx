<Tip>
  **When to use:** write to the personal scope (the default) for anything about one user; to a `team:` or `project:` scope for knowledge a group shares. See [Choosing an API](/concepts/choosing-apis#personal-or-shared-memory).
</Tip>

A scope id is `"<kind>:<value>"` with kind `user`, `team`, `org`, or `project`. See [Users, teams, and scopes](/concepts/scopes) for the model.

## Write scope

Every write method accepts `scope`:

| Method | `scope` |
| --- | --- |
| `conversations.remember(turns, *, session_id, metadata=None, scope=None)` | ✓ |
| `documents.add(content, *, ..., scope=None)` / `tex.add(...)` | ✓ |
| `documents.update(id, *, ..., scope=None)` | ✓ |
| `documents.batch_add(documents, *, ..., scope=None)` | ✓ |
| `memories.add(memories, *, container_tag=None, scope=None)` | ✓ |
| `memories.update_memory(..., scope=None)` | ✓ |
| `episodes.store(messages, *, ..., scope=None)` | ✓ |
| `preferences.store(preferences, *, metadata=None, scope=None)` | ✓ |
| `db.query(query, params=None, *, scope=None)` | ✓ |

Resolution for each write:

1. The call's `scope`, if given
2. Otherwise the client's `default_scope`
3. Otherwise nothing is sent and the server stamps your personal `user:<user_id>` scope

```python
from tex import Tex

alice = Tex(api_key=KEY, base_url=BASE, org_id=ORG, user_id="alice",
            default_scope="team:fpa-pod")

alice.memories.add([{"content": "FY27 plan uses 4% merit increase"}])          # team:fpa-pod
alice.documents.add("Q3 forecast memo …", scope="project:budget-cycle-2027")   # project
alice.conversations.remember(turns, session_id="notes", scope="user:alice")    # personal
```

## Read scope

`recall` reads every visible scope unless you narrow it:

```python
alice.recall("merit assumptions", session_id="s1")                               # all visible scopes
alice.recall("merit assumptions", session_id="s1", scope="team:fpa-pod")         # only team:fpa-pod
```

`default_scope` never narrows reads.

## Validation

The SDK checks the **shape** of every scope before sending — at construction for `default_scope`, per call for `scope`:

```python
from tex import InvalidScopeError

try:
    alice.recall("x", session_id="s1", scope="finance")
except InvalidScopeError as e:     # also a ValueError
    print(e)  # invalid scope 'finance': expected '<kind>:<value>', e.g. 'team:eng'
```

**Membership** is checked by the server.

## Handling `403 scope_not_visible`

```python
from tex import PermissionDeniedError

try:
    alice.conversations.remember(turns, session_id="s1", scope="team:finance")
except PermissionDeniedError as e:
    body = e.details.get("details", {}) if isinstance(e.details, dict) else {}
    if body.get("error") == "scope_not_visible":
        print("visible scopes:", body["visible_scopes"])
```

On a write, the server rejects the request before doing any work. On a narrowed `recall`, the same code is returned for a scope outside your read-set.

## Managing memberships

A user sees `user:<user_id>`, `org:<org_id>`, plus every `team:` / `project:` scope granted to them. Since SDK 1.3.0, your org admin key manages those grants directly with `tex.scopes` (calls [`/me/scope-memberships`](/api-reference/account/scope-memberships)) — no request to Tex needed.

```python
from tex import Tex

admin = Tex(api_key=OWNER_KEY, base_url="https://api.getmetacognition.com")   # no user_id=

grant = admin.scopes.grant("alice", "team:fpa-pod")          # role="member" by default
print(grant.created, grant.membership.role, grant.note)

for m in admin.scopes.list(scope="team:fpa-pod").memberships:
    print(m.user_id, m.role)

admin.scopes.revoke("alice", "team:fpa-pod")
```

<Warning>
  `tex.scopes` needs an **org admin key** (`admin` or `*`) on a client built **without** `user_id=`. A per-user client — or a token-broker key, or a device token — gets `PermissionDeniedError` (`403`), so a user can never grant themselves a scope. The org is always the key's own org.
</Warning>

### `scopes.grant`

```python
tex.scopes.grant(user_id: str, scope: str, *, role: str = "member") -> ScopeGrantResult
```

- Only `team:` and `project:` scopes. A `user:` scope (personal to its user) or an `org:` scope (already implicit for every member) raises `ScopeNotDelegableError` before any request.
- A malformed scope raises `InvalidScopeError`; an empty `user_id` or `role` raises `ValueError`.
- Idempotent: granting an existing membership returns `created=False`; a different `role` updates the stored role.
- A user who hasn't signed in yet can be granted a scope. It applies from their first token.

### `scopes.list`

```python
tex.scopes.list(*, user_id: str | None = None, scope: str | None = None) -> ScopeMembershipList
```

Your org's grants, optionally filtered. Implicit `user:` / `org:` scopes are never listed.

### `scopes.revoke`

```python
tex.scopes.revoke(user_id: str, scope: str) -> ScopeRevokeResult
```

Raises `NotFoundError` if the grant doesn't exist. Revoking removes access, not data: memory already written into the scope stays for the remaining members. To remove the data, use [`tex.deletions`](/sdk/deletions).

### Return types

```python
ScopeGrantResult(membership: ScopeMembership, created: bool, note: str, raw)
ScopeMembershipList(memberships: list[ScopeMembership], total: int, raw)
ScopeMembership(id: int | None, org_id: str, user_id: str, scope_id: str, role: str, created_at: str | None, raw)
ScopeRevokeResult(removed: bool, note: str, raw)     # the server answers 204; removed is always True
```

### Propagation

A grant or revocation reaches the user on their **next token refresh — allow up to 1 hour**. Tokens already issued keep their old scopes until then: a new grant isn't visible immediately, and a revoked scope stays readable until the token refreshes. `result.note` repeats this on every change.

<Note>
  Tex operators manage grants across orgs with `tex.admin.scopes.*` ([platform endpoints](/api-reference/admin/scope-memberships)). A customer key gets `403` there.
</Note>
