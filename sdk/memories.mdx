<Tip>
  **When to use:** for a fact, preference, or decision someone explicitly wants kept. Each memory is recallable immediately and can be edited or deleted on its own. For the running conversation, use [`remember`](/sdk/conversations-remember); for files, [`documents.add`](/sdk/documents). See [Choosing an API](/concepts/choosing-apis).
</Tip>

Memories are short facts — "prefers the driver-based forecast model" — written directly, without a conversation. They are stored in the long-term store and, best-effort, in the active tier. Calls `/v4/memories`.

## `memories.add`

```python
tex.memories.add(
    memories: list[dict],
    *,
    container_tag: str | None = None,
    scope: str | None = None,
    inactivity_timeout_seconds: int | None = None,   # 1.2.1+
) -> MemoryWriteResponse     # document_id, memories, durable_tier_error, active_tier_error, raw
```

Each item: `{"content": str, "isStatic": bool (optional), "metadata": dict (optional, flat)}`. Items without `content` are skipped; if none remain the server returns `400`.

```python
resp = tex.memories.add(
    [
        {"content": "FP&A pod uses the driver-based forecast model for FY27"},
        {"content": "Alice owns the EMEA travel budget", "metadata": {"region": "emea"}},
    ],
    scope="team:fpa-pod",
)
for m in resp.memories:
    print(m.id, m.memory)
```

`memories.add` creates new ids on every call — it is not idempotent.

If one storage tier failed while the other accepted the write, the call still succeeds and says so: `resp.durable_tier_error` (long-term memory failed) or `resp.active_tier_error` (active memory failed). Both are `None` on success. These attributes need SDK 1.3.1+ and are `None` on servers that don't send them.

`inactivity_timeout_seconds` (SDK 1.2.1+, 300–86,400) sets the [inactivity window](/concepts/memory-model#inactivity-window) of the active-tier episode these memories are written to; it is sent as `inactivityTimeoutSeconds`.

## `memories.update_memory`

```python
tex.memories.update_memory(
    container_tag: str | None = None,
    new_content: str | None = None,
    *,
    id: str | None = None,
    content: str | None = None,
    metadata: dict | None = None,
    scope: str | None = None,
    inactivity_timeout_seconds: int | None = None,   # 1.2.1+
) -> MemoryUpdateResponse   # id, memory, version, parent_memory_id, root_memory_id, created_at,
                            # superseded, durable_tier_error, active_tier_error (1.3.1+)
```

Writes a new version and **retires the one it replaces**. Identify the memory to edit by `id`, or by exact `content`. `new_content` is required. `404` if the memory isn't found.

```python
v2 = tex.memories.update_memory(new_content="Alice and Bob own the EMEA travel budget",
                                id="3f0c…")
print(v2.id, v2.version, v2.parent_memory_id, v2.root_memory_id)
```

### What an edit does

- **The new version is a new memory** with a new `id`. `version` counts up from the memory you edited (a memory from `memories.add` is version 1, so its first edit is 2, then 3, 4, …). `parent_memory_id` is the version you edited; `root_memory_id` stays the original id for the whole chain.
- **The previous version is retired.** It stops being returned by recall, search, and `GET /v4/memories`, in both tiers, so an agent never sees two answers for the same fact.
- **Edit the latest version.** Pass the newest `id` for the next edit. A retired version can't be read by the edit path, so editing it starts a separate chain at version 2 and the response reports `superseded: false`.

### Reading history

A retired version stays readable by its id through [`documents.get`](/sdk/documents) (`GET /v3/documents/{id}`), marked as superseded:

```python
old = tex.documents.get("3f0c…")
old.status                       # "superseded"
old.content                      # the pre-edit text
old.metadata["supersededBy"]     # id of the version that replaced it
old.metadata["supersededAt"]     # ISO 8601
old.metadata["version"], old.metadata["rootMemoryId"]
```

To walk a chain, follow `supersededBy` forward from the root, or keep the ids `update_memory` returns.

### When retiring the previous version fails

The edit still returns `200`: the new version is already written, and failing the request would invite a retry that forks the chain into two new versions. The response says what happened instead (SDK 1.3.1+):

| Attribute | Meaning |
| --- | --- |
| `superseded` | `True` when the previous version was retired in both tiers; `False` when it may still be returned alongside the new one |
| `durable_tier_error` | Set when the previous version is still live in long-term memory, or its consolidated episode event couldn't be deleted |
| `active_tier_error` | Set when the active-tier write or retirement failed |

All three are `None` on servers that don't send them. On SDK 1.3.0, read `resp.raw.get("superseded")`, `"durableTierError"`, and `"activeTierError"`.

```python
v3 = tex.memories.update_memory(new_content="…", id=v2.id)
if v3.superseded is False:
    # Don't retry the edit. Remove the old version explicitly instead.
    tex.memories.forget(id=v2.id, reason="superseded")
```

## `memories.forget`

```python
tex.memories.forget(
    container_tag: str | None = None,
    *,
    id: str | None = None,
    content: str | None = None,
    reason: str | None = None,
) -> MemoryForgetResponse   # id, forgotten, raw
```

Deletes one memory by `id` or exact `content`. `404` if not found.

```python
tex.memories.forget(id="3f0c…", reason="user asked to forget")
```

- The memory stops being returned by active recall, deep recall, search, and `GET /v4/memories` immediately, and its vectors are withdrawn.
- It's a soft delete: storage is reclaimed later. Deleted facts don't come back — if the same information is added again, it's stored as a new memory.
- If the memory's conversation was already consolidated, its own episode event is deleted too; a memory forgotten while its conversation is consolidating is skipped by consolidation.
- The response can include `durableTierError` (the episode event couldn't be deleted) or `activeTierError` (the active copy couldn't be hidden); both are omitted when there's nothing to report. `MemoryForgetResponse` has no attributes for them — read `resp.raw.get("durableTierError")` and `resp.raw.get("activeTierError")`. The memory itself is deleted whenever `forgotten` is `True`.
- `forget` acts on the memory as the calling user; it works from a per-user client. To delete another user's memory with a receipt, or a whole scope or user, use [`tex.deletions`](/sdk/deletions).
- Matching by `content` needs the exact text.

## `container_tag`

- **Key-only client** (`Tex(api_key=...)`): `container_tag` selects the end user the call acts for.
- **Per-user client**: omit it or pass the user's own id; anything else is `403 container_tag_not_permitted`.

Tags must match `^[a-zA-Z0-9_-]+$` and be ≤ 100 chars.

## Reading memories back

An agent reads these back with [`recall`](/sdk/recall) — memories from `memories.add` are returned alongside conversation turns. Use [`search.memories`](/sdk/search) for listing and search screens. See [Choosing an API](/concepts/choosing-apis).
