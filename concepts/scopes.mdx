Every turn and every recall is keyed by `(org_id, user_id, session_id)`.

| Field | Set by | Required |
| --- | --- | --- |
| `org_id` | The JWT (your API key) — server-injected | ✓ |
| `user_id` | The JWT, or override per-call for sub-user scoping | ✓ |
| `session_id` | **You, per call.** | ✓ |

`org_id` is locked to your API key. You almost never set it manually. `session_id` is where you do the work.

## Picking a `session_id`

Free-form string. Reuse, don't enumerate.

  <Card title="One conversation" icon="message">

## Multi-user SaaS

Each end-user gets their own memory. **Encode the end-user into the `session_id`** with one shared client:

```python
tex = Tex(api_key=os.environ["TEX_API_KEY"], base_url=BASE_URL)

def chat(user_msg: str, x_user_id: str, conv_id: str):
    sid = f"u_{x_user_id}-{conv_id}"
    hits = tex.recall(q=user_msg, session_id=sid)
    ...
```

One API key, one bill, one client, full isolation between end-users.

<Note>
  Per-call `user_id` scoping is on the SDK roadmap (1.2). Until then, encoding into `session_id` is the cleanest pattern. See the [multi-tenant SaaS recipe](/recipes/multi-tenant-saas).
</Note>
