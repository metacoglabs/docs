## What is Tex?

Tex is a hosted memory layer for AI agents. You stream conversation turns to it; it builds a multi-modal memory store — raw turns, extracted observations, entities, and a temporal index. When your agent needs context, you call `recall(...)` and get back the relevant slice of history, scored and ready to drop into a system prompt.

It's the layer between your agent loop and your LLM. Stop dragging entire chat histories into prompts. Stop maintaining your own retention logic. Stop forgetting what your user told you last week.

## How it works

<Steps>
  <Step title="Remember">
    Push conversation turns to Tex through `tex.conversations.remember(...)`. Active memory is queryable in milliseconds; passive enrichment (observations, entity graph) builds in the background.
  </Step>
  <Step title="Recall">
    On every new user turn, call `tex.recall(query)`. You get back scored turns + observations + a confidence number — drop them into your system prompt.
  </Step>
  <Step title="Generate">
    Your LLM produces an answer with full context but a small prompt. Persist the new turns back to Tex. Loop.
  </Step>
</Steps>

## Why a memory layer?

  <Card title="Bounded prompts" icon="ruler">

  </Card>
  <Card title="Temporal awareness" icon="clock">
    "What did I say about pricing two weeks ago?" is a first-class query — not a vector search hack.
  </Card>
  <Card title="Confidence scoring" icon="gauge">
    Every recall returns a calibrated confidence. Gate fallback behavior on it.
  </Card>

## When *not* to use Tex

Tex is for **conversational, per-user, time-aware memory.** Use a regular vector DB for:

- Static documentation lookup ("what does the manual say about X?")
- One-shot RAG over a corpus that doesn't accumulate per-user
- Cold storage / archival
- Bulk file ingestion at GB scale

Use both? Common. Tex remembers what *the user* said. Your vector DB knows what *the world* said. Combine in your prompt.
