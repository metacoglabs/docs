title: "Agent memory (LangChain)"
description: "Use Tex as an agent's memory tool."
---

Two patterns:

1. **Memory tool.** The agent calls `recall` when it needs context.
2. **Pre-prompt injection.** Your controller code calls `recall` before the LLM call and adds the results to the prompt.

Pattern 2 is simpler and usually enough. Pattern 1 suits autonomous agents.

<Note>
  Build the client **per end user** (`user_id=`). `session_id` groups turns into a conversation but does not isolate reads. See [Per-user clients](/sdk/per-user-clients).
</Note>

## Pattern 1: memory as a tool

```python
# pip install tex-sdk langchain langchain-openai
import os
from datetime import datetime, timezone

from langchain.tools import tool
from tex import Tex

tex = Tex(
    api_key=os.environ["TEX_API_KEY"],
    base_url=os.environ["TEX_BASE_URL"],
    org_id=os.environ["TEX_ORG_ID"],   # required on SDK 1.2.0–1.2.1; recommended on 1.2.2+
    user_id="agent-1",                 # the identity whose memory this agent uses
)
SESSION = "agent-1-task-42"


def now_iso() -> str:
    return datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")


@tool
def recall_memory(query: str) -> str:
    """Look up the agent's long-term memory for relevant context.
    Returns up to 5 most-relevant past statements."""
    hits = tex.recall(query, session_id=SESSION, top_k=5, mode="deep")
    items = hits.hits.observations + hits.hits.turns
    if not items:
        return "(no relevant memory)"
    return "\n".join(f"- {h.text}" for h in items[:5])


@tool
def remember_fact(text: str) -> str:
    """Persist a fact for future recall."""
    # Turn roles must be "user" or "assistant" — "system" is rejected with 422.
    tex.conversations.remember(
        [{"role": "assistant", "text": text, "timestamp": now_iso(), "observations": [text]}],
        session_id=SESSION,
    )
    return "remembered"
```

Pass `[recall_memory, remember_fact]` to your agent constructor, such as `create_react_agent` or LangGraph's prebuilt agent. The agent decides when to call `recall_memory`. That helps in multi-step plans where only some steps need history.

`mode="deep"` also searches long-term memory. `mode="active"` only sees conversations written within the inactivity window (30 minutes by default). See [Recall](/sdk/recall).

## Pattern 2: injection at the controller level

```python
import os
from datetime import datetime, timezone

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from tex import Tex

prompt = ChatPromptTemplate.from_messages([
    ("system", "Relevant memory about the user:\n{memory}"),
    ("user", "{input}"),
])
llm_chain = prompt | ChatOpenAI(model="gpt-4o")


def now_iso() -> str:
    return datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")


def chain(tex: Tex, user_msg: str, sid: str) -> str:
    # 1. Recall
    hits = tex.recall(user_msg, session_id=sid, top_k=5)
    memory = "\n".join(f"- {h.text}" for h in hits.hits.turns)

    # 2. Generate
    answer = llm_chain.invoke({"memory": memory, "input": user_msg}).content

    # 3. Persist
    tex.conversations.remember(
        [
            {"role": "user", "text": user_msg, "timestamp": now_iso()},
            {"role": "assistant", "text": answer, "timestamp": now_iso()},
        ],
        session_id=sid,
    )
    return answer
```

`tex` is the signed-in user's client. Build it as shown in the [FastAPI recipe](/recipes/fastapi).

## Replacing `BaseChatMemory`

LangChain's built-in memory (`ConversationBufferMemory` and similar) is a buffer. Tex is retrieval. The migration looks like this:

```python
# BEFORE — full history in the prompt
memory = ConversationBufferMemory()
chain = ConversationChain(llm=llm, memory=memory)

# AFTER — top-k relevant turns, regardless of recency
hits = tex.recall(user_msg, session_id=sid, top_k=5)
prompt = stitch(hits.hits.turns, user_msg)
answer = llm.invoke(prompt)
tex.conversations.remember(turns, session_id=sid)
```

You stop maintaining a sliding window, and the retrieved context stays bounded by `top_k`.
