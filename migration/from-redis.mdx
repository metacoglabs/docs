---
title: "From Redis"
description: "Replace your Redis-backed conversation log with Tex memory."
---

This migration is for chatbots that store chat history in Redis (or Postgres, or Mongo) and put the whole history into every prompt.

## The pattern you're replacing

```python before.py
# Append every turn
redis.rpush(f"hist:{sid}", json.dumps({"role": "user", "text": user_msg}))
redis.rpush(f"hist:{sid}", json.dumps({"role": "assistant", "text": reply}))

# Load the whole history into the prompt
history = [json.loads(x) for x in redis.lrange(f"hist:{sid}", 0, 50)]
prompt = build_prompt(history, user_msg)
reply = llm(prompt)
```

Pain points:
- It hits the LLM context limit fast.
- "Last 50" is a guess, so older relevant context gets dropped.
- Redis storage grows forever.

## The Tex version

```python after.py
tex = tex_for_user(user_id)   # one Tex identity per end user — see /sdk/per-user-clients

hits = tex.recall(user_msg, session_id=sid, top_k=8)
prompt = build_prompt_with_memory([h.text for h in hits.hits.turns], user_msg)
reply = llm(prompt)
tex.conversations.remember(
    [
        {"role": "user", "text": user_msg, "timestamp": now_iso()},
        {"role": "assistant", "text": reply, "timestamp": now_iso()},
    ],
    session_id=sid,
)
```

What changes:

1. **Bounded prompts.** You pull the *relevant* 8 turns, however many exist.
2. **Cross-session continuity.** `recall` searches all of a user's conversations, not only `sid`. `session_id` groups turns into one conversation but doesn't filter reads.
3. **Isolation by identity.** Keys like `hist:{user}:{sid}` kept users apart in Redis. In Tex, give each end user their own client with `user_id=`. See [Per-user clients](/sdk/per-user-clients).

<Note>
  `mode="active"` (the default) searches conversations with writes within the inactivity window (30 minutes by default). Older conversations are consolidated into long-term memory and need `mode="deep"`. Backfilled history is usually old, so query it in deep mode.
</Note>

## Backfill plan

<Steps>
  <Step title="Dump Redis to a script">
    For each `hist:*` key, fetch all turns with their **original** timestamps and the end user they belong to.
  </Step>
  <Step title="Bulk-remember">
    ```python
    for (user_id, sid), turns in redis_history.items():
        formatted = [
            # role must be "user" or "assistant"; timestamp is required (ISO 8601)
            {"role": t["role"], "text": t["text"], "timestamp": t["ts"]}
            for t in turns
            if t["role"] in ("user", "assistant") and t["text"].strip()
        ]
        if formatted:
            tex_for_user(user_id).conversations.remember(formatted, session_id=sid)
    ```

    Split very large histories into batches of a few hundred turns per call. Requests are capped at 50 MB, and each call counts against your daily `tokens_in` quota (1,000,000 per UTC day).
  </Step>
  <Step title="Verify">
    Pick 10 sessions. For each, run a known query and compare the retrieved turns with your Redis log. Check that:

    - `len(resp.active_fragment_ids)` matches the number of turns sent, plus any `observations`.
    - `recall(<a known phrase>, session_id=sid, mode="deep")` finds the right turn.
  </Step>
  <Step title="Shadow mode">
    Run **both** read paths in production for a week. Log how often Tex returns no relevant turns. If that rate is within your tolerance, continue.
  </Step>
  <Step title="Cut over the read path">
    Switch the prompt to Tex hits. Keep writing to Redis for one more week as a backup.
  </Step>
  <Step title="Cut over the write path">
    Stop appending to Redis and drop the keys.
  </Step>
</Steps>

<Warning>
  **Retries aren't free.** Replaying an identical turn (same user, session, timestamp and text) doesn't create duplicate active-tier fragments. The long-term write and token metering are **not** deduplicated, so make the backfill resumable instead of re-running it from the start.
</Warning>

## Edge cases

- **Streaming responses.** Call `remember` *after* the stream completes, in a background task so the next request isn't delayed.
- **System messages.** Don't migrate them. Tex accepts only `user` and `assistant` roles, and system prompts add no recall value.
- **Tool calls.** Store the *result* of a tool call as an assistant turn, not the raw JSON. Recall returns text.
- **Audit log.** Tex isn't an audit store. Keep an append-only log for compliance and use Tex for retrieval.
